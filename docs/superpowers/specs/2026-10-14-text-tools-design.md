# Text Tools — Design

Date: 2026-10-14
Status: design approved in conversation 2026-10-14; this document awaits the owner's review

## 1. Purpose

A free set of text generators and converters at `/text`. It is the third tool in the pokerji suite. Someone opens the page, picks a tool, and copies the result: a password, a passphrase, a random string, an identifier, the same words in another case, an encoded or decoded value, a hash, a tidied list.

It is for anyone who needs one of these in the middle of other work, most often a developer or an administrator at a desk.

Security and privacy outrank feature scope and delivery speed, as everywhere in this repository. The tool runs entirely in the browser. Nothing typed into it or generated by it is sent to the server, and nothing is stored, in the browser or anywhere else.

The owner considered letting the server do the work and keep nothing. That was turned down: no tool here needs a server, a visitor can check "no request was made" but cannot check "the server forgot", and a secret that crosses the network has passed through a proxy and a process that this design keeps it out of.

### Success criteria

- Someone can go from opening `/text` to a strong password on the clipboard with one press.
- Every result on the page can be copied, one at a time or all together.
- Every generated value comes from the browser's cryptographic random source, chosen without bias.
- The strength shown for a password or passphrase is the true figure for the rule that made it.
- No request made by the page carries anything typed or generated, and the page writes nothing to browser storage.

### Out of scope for the first version

Saving or remembering anything, settings included; share links; masking results on screen; password-storage hashes (Argon2, bcrypt, scrypt); MD5 and SHA-1; files as input; JSON, timestamp and number-base tools; word lists other than the EFF long list; languages other than English; working without JavaScript.

## 2. Architecture

### Where things live

```
packages/text-tools        every rule: samplers, generators, case and slug
                           rules, encoders, line tools, counts, the word
                           list reader; no I/O, no DOM, no framework
apps/web/src/routes/text   the page
apps/web/src/lib/text      the page's components and its one state module
apps/web/static/text       the word list and its licence record
```

`packages/text-tools` follows `packages/schema-builder`: plain TypeScript, tested with Vitest, exported from `src/index.ts`. It has no dependencies.

Nothing is added to `packages/poker-server`, `packages/protocol`, Postgres, Valkey, the WebSocket path or the metrics. The server's only new work is serving one page and one static file. There is no form action, no endpoint and no cookie for this tool.

### Pages

| URL | Surface |
|---|---|
| `/text` | The tools |
| `/text/eff_large_wordlist.txt` | Static file: the word list |
| `/text/LICENSES.md` | Static file: the word list's licence record |

`/text` is public and indexable. It uses `Seo.svelte` and is added to `/sitemap.xml`. Nothing exists below it except static files.

### Randomness and the clock are arguments

The package never reaches for a random source or a clock.

- Every generator takes `random: (count: number) => Uint8Array`, which must return `count` fresh random bytes. The page passes a function that calls the browser's `crypto.getRandomValues`. Tests pass a fixed sequence.
- UUID v7 and ULID take `now`, a number of milliseconds, as the poker engine takes its clock.

`Math.random` is used nowhere, in the package or the page. If the browser has no cryptographic random source, the generators say so and produce nothing. There is no fallback.

### What the package may touch

A test (`purity.test.ts`, like the builder's) reads the package source and fails on any Node import and on `window`, `document`, `localStorage`, `sessionStorage`, `navigator`, `fetch`, `crypto`, `Math.random`, `Date`, `atob` and `btoa`. It also fails on any import that is not one of the package's own files, and on `globalThis`, `self`, `process`, `Buffer`, `performance`, `Temporal`, `require`, `XMLHttpRequest`, `WebSocket` and `indexedDB`. The only platform objects the package uses are `TextEncoder`, `TextDecoder` and `Intl.Segmenter`, which do no I/O. `Intl.Segmenter` is made on first use, never when the package loads; in a browser without it, the count tool counts code points and every other tool is unaffected.

### The converters' worker

Case, Slug, Count, Encode and decode, and Lines in any order but Shuffled do their work in a Web Worker: a script served by this site (`apps/web/src/lib/text/convert.worker.ts`), started the first time a converter is used. Typed text goes to it inside the browser by `postMessage` and the answer comes back the same way; nothing crosses the network, and the worker makes no request and keeps nothing. While it works, the last answer stays on screen; keystrokes that arrive meanwhile replace the next job instead of queueing. Copy pressed before an answer arrives works the answer out on the page at once, so a copy never holds results for older text. A shuffle stays on the page, so the order copied is the order shown. Where workers are missing or the script fails to load, the same functions run on the page. The Content Security Policy needs no change: a worker is a script, and `script-src 'self'` allows this site's own.

Added on 2026-10-15 (Impeccable overdrive, direction "never hesitates"): at the typed-text limit the slowest keystroke in Case was 272 to 312 ms; the browser test now requires under 120 ms.

### Hashing is the page's

SHA hashing is one call to the browser's `crypto.subtle.digest`. The page makes that call; the package supplies the text-to-bytes and bytes-to-hex steps.

## 3. Limits

All in one `LIMITS` object in the package. The page's fields carry the same numbers, and the package checks them again itself.

| Limit | Value |
|---|---|
| Password length | 8 to 256 |
| Random string length, in characters | 1 to 256 |
| Random string size, in bytes | 1 to 128 |
| Results at once | 1 to 100 |
| Passphrase words | 3 to 12 |
| PIN digits | 4 to 12 |
| Number bounds | −1,000,000,000,000,000 to 1,000,000,000,000,000 |
| Sides on a die | 2 to 1,000 |
| Own alphabet | 2 to 256 distinct characters |
| Typed text, any converter or list | 100,000 characters |
| Redraws before a sampler gives up | 1,000 |

Every function that takes typed text returns a result or a finding; none throws on any input. Over a limit, the finding says which limit.

## 4. Sampling

One function, `below(n, random)`, returns a whole number from 0 to n − 1, each equally likely. It finds how many bits n − 1 needs, draws that many whole bytes, masks off the spare bits, and draws again if the value is n or more. It never takes a remainder. At least half of all draws are accepted.

Everything random is built on it: a character from an alphabet, a word from the list, a number in a range, a die, a shuffle (Fisher–Yates), a pick from a list. Raw random bytes, for hex and Base64 strings and for identifiers, come straight from `random`.

A random source that keeps returning rejected values would loop for ever, so `below` gives up after `LIMITS` redraws and the tool reports that it could not generate. A source that returns the wrong number of bytes is refused the same way.

## 5. Generators

Each generator makes between 1 and 100 results at once, each drawn independently.

### Password

Options: length (default 20); lowercase, uppercase, digits and symbols (all on by default; at least one must stay on); no look-alikes (off by default).

- Symbols are `! @ # $ % ^ & * ( ) - _ = + [ ] { } ; : , . ? /`.
- No look-alikes removes `0 O o 1 l I |` from whichever classes hold them.
- A password contains at least one character from each class that is on. It is drawn whole and drawn again until it does, so every password the rule allows is equally likely. Characters are never forced into positions.
- Strength is the base-2 logarithm of the number of passwords the rule allows, counted exactly by inclusion and exclusion over the classes, and rounded down to a whole number of bits.

### Passphrase

Options: words (default 6); separator, one of hyphen, space, full stop and underscore (default hyphen); capitals (off); add a digit (off).

- Words are drawn from the EFF long list, with repeats allowed.
- Capitals makes the first letter of every word a capital. It adds no strength and none is claimed.
- Add a digit puts one digit, 0 to 9, after one word chosen at random.
- There is no "no separator" choice: the long list is not built to be read back without one.
- Strength is words × log2(7,776), plus log2(10 × words) with a digit, rounded down.

### Random string

| Kind | Sized in | Made by |
|---|---|---|
| Hex | bytes (default 16) | random bytes, written as lowercase hex |
| Base64 | bytes (default 32) | random bytes, standard alphabet, padded |
| Base64URL | bytes (default 32) | random bytes, URL-safe alphabet, no padding |
| Digits | characters (default 16) | `0` to `9` |
| Letters | characters (default 16) | lowercase, uppercase or both |
| Alphanumeric | characters (default 24) | letters and digits |
| Own alphabet | characters (default 16) | the characters typed |

An own alphabet is refused if it has fewer than 2 or more than 256 characters, a repeated character, white space or a control character. Characters are counted as Unicode code points.

Strength is shown for every kind: 8 bits a byte, or length × log2(alphabet size).

### PIN and number

- PIN: digits only, of the chosen length (default 6). Leading zeros are kept.
- Number: a whole number between two bounds, both included. If the first bound is the larger, the two are swapped.

### Identifier

| Kind | Form |
|---|---|
| UUID v4 | RFC 9562 version 4: 122 random bits |
| UUID v7 | RFC 9562 version 7: 48 bits of time in milliseconds, 74 random bits |
| ULID | 48 bits of time, 80 random bits, in Crockford Base32 |
| Short id | 21 characters from `A–Z a–z 0–9 _ -`, 126 random bits |

Several UUID v7 or ULID values made at once share a time and are each fully random beyond it; they are not made to sort in the order shown. The page says, beside these two kinds, that the value contains the time it was made.

### Chance

- Dice: the chosen number of dice with the chosen number of sides (default 6); each result and the total are shown.
- Coin: the chosen number of flips, each heads or tails.
- Pick from a list: one line of typed text for each result asked for, without picking the same line twice. Asking for more than the list holds gives the whole list, shuffled.

## 6. Converters

A converter reads one text box and shows its results as the text changes. A list is split into lines at `\r\n`, `\n` or `\r` and joined again with `\n`.

### Case

Twelve forms are shown at once, each with its own Copy.

| Form | Example for `parseHTTPResponse2 now` |
|---|---|
| camel | `parseHttpResponse2Now` |
| Pascal | `ParseHttpResponse2Now` |
| snake | `parse_http_response_2_now` |
| CONSTANT | `PARSE_HTTP_RESPONSE_2_NOW` |
| kebab | `parse-http-response-2-now` |
| Train | `Parse-Http-Response-2-Now` |
| dot | `parse.http.response.2.now` |
| path | `parse/http/response/2/now` |

| Form | Example for `the return of the iPhone: a buyer's guide` |
|---|---|
| Title | `The Return of the iPhone: A Buyer's Guide` |
| Sentence | `The return of the iPhone: a buyer's guide` |
| UPPER | `THE RETURN OF THE IPHONE: A BUYER'S GUIDE` |
| lower | `the return of the iphone: a buyer's guide` |

The eight programming forms split the text into words first:

- at any run of characters that are neither letters nor digits (apostrophes are dropped, so `don't` is one word);
- where a lowercase letter meets an uppercase one (`parseHTTP`);
- before the last capital of a run of capitals that is followed by a lowercase letter (`HTTPResponse` is `HTTP`, `Response`);
- where a letter meets a digit.

Letters and digits are Unicode's, not only ASCII, and a letter keeps the combining marks written after it. camel and Pascal join a digit to the word before it. Each line of the input is converted on its own.

The four writing forms keep the text's spacing and punctuation.

- Title: the first letter of each word is a capital. The words a, an, and, as, at, but, by, for, if, in, nor, of, on, or, per, the, to, via and vs stay lowercase unless first, last, or straight after a colon.
- Sentence: everything is lowercase except the first letter of each sentence and the word I.
- In both, a word that already has a capital after its first letter (`iPhone`, `NASA`) is left exactly as typed wherever it stands, unless the whole text is in capitals.

### Slug

Accents are removed (Unicode decomposition, combining marks dropped), with ß, æ, œ, ø, đ, ł and þ written as ss, ae, oe, o, d, l and th. The text is made lowercase, every run of anything but `a–z` and `0–9` becomes one hyphen, and hyphens at the ends are removed. Each line is converted on its own. A line with nothing left gives an empty line, and the page says so.

### Encode and decode

One direction switch. Text is turned into bytes as UTF-8.

| Form | Encoding | Decoding accepts |
|---|---|---|
| Base64 | standard alphabet, padded | white space anywhere; padding present or absent |
| Base64URL | URL-safe alphabet, no padding | the same |
| Hex | lowercase, two digits a byte | white space and colons between bytes; either case |
| URL | every character except `A–Z a–z 0–9 - _ . ! ~ * ' ( )` | `%XX` sequences; `+` is left as `+` |
| HTML entities | `& < > " '` | decimal and hex numbers, and the named entities of HTML 4 with `&apos;`; `&lang;` and `&rang;` give the characters browsers give (U+27E8, U+27E9) |

Malformed input gives a finding that says what is wrong (a character outside the alphabet, an odd number of hex digits, a broken `%` sequence). Decoded bytes that are not valid UTF-8 are shown as hex, with a line saying that the result is not text. An entity that is unknown or names an impossible character is left as typed.

HTML entities are decoded from a fixed table in the package. The DOM is never used to decode them, and no result is ever rendered as HTML.

### Hash

SHA-256, SHA-384 and SHA-512 of the text exactly as typed, as UTF-8, shown in lowercase hex. Nothing is shown for an empty box. The page says that a line ending counts, and that these hashes are not a way to store passwords.

### Lines

Steps are applied in this order, each one optional:

1. Trim the white space at both ends of each line.
2. Remove blank lines.
3. Remove repeated lines, keeping the first of each; an option ignores case.
4. One of: keep the order, sort A to Z, sort Z to A, reverse, shuffle.
5. Number the lines (`1. `, `2. `, and so on).

Sorting is by Unicode code point, with an option to ignore case, so the order does not depend on the browser's language. Shuffle uses the sampler in section 4 and has a Shuffle again button.

### Count

Characters (as a reader counts them, by grapheme), characters without white space, words (runs of anything but white space), lines, and bytes as UTF-8.

## 7. The word list

### Source and licence

The EFF long word list for passphrases: 7,776 words, published by the Electronic Frontier Foundation under the Creative Commons Attribution 3.0 United States licence, at `https://www.eff.org/files/2016/07/18/eff_large_wordlist.txt`.

It is vendored as `apps/web/static/text/eff_large_wordlist.txt`, exactly as published. `apps/web/static/text/LICENSES.md` records the source, the licence, the date fetched and the file's SHA-256. The page credits the EFF and links to the licence and to `LICENSES.md`. Nothing is fetched from eff.org when the app is built or run.

The plan's step that downloads the file is an action the owner approves when it is reached.

### Reading it

The published file has a dice number and a word on each line. `readWordList(text)` in the package returns the words, or a refusal unless there are exactly 7,776 lines, each a five-digit dice number, a tab and a word of lowercase letters and hyphens, with no word repeated.

The package also holds the file's SHA-256 as a constant. A test compares the constant, the row in `LICENSES.md` and the file.

### Loading

The page fetches the list from this site the first time the passphrase tool is opened, not before. It hashes what arrived, compares the hash with the constant, and then reads it with `readWordList`. If either check fails, or the fetch does, the passphrase tool says it could not load its words and offers to try again. The other tools are unaffected.

## 8. The page

The visual system is the suite's: the tokens in `apps/web/src/app.css`, the components in `apps/web/src/lib/ui` and the rules in `DESIGN.md`. The owner's instruction for new tools is to keep the existing design and add only missing components, matching the existing ones. The design direction for this page is `2026-10-14-text-tools-design-direction.md`.

### Layout

- A band with the heading "Text tools" and one line of promise, as on `/schema`.
- Below it, two labelled groups, Generate and Convert, each a row of tool tabs: Password, Passphrase, Random string, PIN and number, Identifier, Chance; then Case, Slug, Encode and decode, Hash, Lines, Count.
- One tool is open at a time. From 64rem its options or text box are in a column on the left and its results in a rail on the right that stays in view; below that, results follow options in one column.
- An "about" section under the tools: what the tools do, where the text goes (nowhere), and the word list's credit.

### The open tool is in the fragment

Each tab is a link to a fragment: `#password`, `#passphrase`, `#random`, `#number`, `#id`, `#chance`, `#case`, `#slug`, `#encode`, `#hash`, `#lines`, `#count`. A browser does not send a fragment to a server, so the server never learns which tool was used. The fragment is matched against that fixed list; anything else opens Password. Nothing typed and no option is ever put in the address.

### Results

- A generator shows results as soon as it opens, again whenever an option changes, and on **Generate again**.
- Results are rows of monospace text, each ending in the existing `CopyButton`. With more than one result there is also **Copy all**, which joins them with line breaks.
- Results are rendered as text only. They wrap; nothing is cut short.
- The clipboard is written only when a Copy button is pressed. If the browser refuses, the page says so and the text is there to select by hand.
- Strength is a line of words under the options ("131 bits"), never a coloured meter.

### Fields

Every field and text box sets `spellcheck="false"`, `autocomplete="off"`, `autocapitalize="off"` and `autocorrect="off"`, so typed text cannot reach a browser's spelling service or its store of saved form entries. Text boxes carry the typed-text limit as `maxlength`.

### Design rules that constrain it

- Yellow marks the one next step, and it is the rail's first control: Generate again on a generator, Copy on a converter with one result, Copy all on a converter with several.
- Red is not used. A refusal is a line of words.
- No inline styles: no `style` attribute and no Svelte `transition:`, `in:`, `out:` or `animate:`.
- No raw colours in components. Both themes to the same standard.
- New components are a tab row and a result row, each derived from an existing pattern (the bar's links, the builder's ruled list).

### Without JavaScript

The page shows a line saying the tools need JavaScript because they run in the browser and nowhere else, as `/schema` does.

## 9. Privacy and data

| Data | Where it is | For how long | Who can read it |
|---|---|---|---|
| Typed text | the page's memory | until the tab closes or the text is cleared | the person at the browser |
| Generated values | the page's memory | until replaced or the tab closes | the person at the browser |
| A copied value | the system clipboard | until the person copies something else | whatever that device allows |
| Options, and which tool is open | the page's memory; the tool's name in the address fragment | until the tab closes | the person at the browser |

The server receives the request for the page and, if the passphrase tool is opened, for the word list, and, once a converter is used, for the converters' worker script. None carries anything typed or generated. The tool sets no cookie, writes nothing to local or session storage, adds no metric, and logs nothing.

No new dependency, third-party script, analytics or outside service is added. The one piece of outside material is the word list, vendored and credited.

### Trust boundaries

- Typed text is untrusted input to the package. Every function checks length first and never throws.
- The word list is checked by hash and by shape before a word is used, though it comes from this site.
- The address fragment is untrusted. It is only ever compared with a fixed list.
- Output is pasted into other systems by the person. The page renders it as text and makes no claim that an encoded value is safe in any particular place.

## 11. Failure behaviour

| What happens | What the page does |
|---|---|
| No cryptographic random source | Generators say they cannot run in this browser; converters work |
| The random source misbehaves | The tool says it could not generate; nothing is shown |
| The word list fails to load or fails a check | The passphrase tool says so and offers to try again |
| `crypto.subtle` is missing | The hash tool says it cannot run in this browser |
| Typed text is over the limit | The tool names the limit and shows no result |
| Input cannot be decoded | A line says what is wrong; no result is shown |
| An option is outside its limits | It is refused with the limit named; the last good results stay |
| The clipboard is refused | A line says so; the text stays selectable |

## 12. Testing

### Package

- `below`: never returns n or more; redraws on a rejected value; gives up after the limit; over a fixed sequence covering every byte value, every outcome comes up equally often.
- Password: each class that is on appears; no look-alike appears when they are off; the strength figure matches a count made by brute force for small alphabets and lengths.
- Passphrase: word count, separator, capitals and the digit; strength figures.
- Random string: every kind; sizes at both limits; each refusal of an own alphabet.
- Identifiers: version and variant bits; the time in a UUID v7 and a ULID read back as `now`; known vectors.
- Chance: totals, picks without repeats, a list shorter than the number asked for.
- Case: a table of inputs for every form, including acronyms, digits, accented letters, apostrophes and several lines.
- Slug, lines and counts: tables of inputs, including emoji and combining marks for the counts.
- Encoders: known vectors; every encode followed by decode returns the input; every kind of malformed input gives its finding; bytes that are not text come back as hex.
- Limits: every function at and just beyond each limit; no function throws for any input in a set of awkward strings (lone surrogates, null characters, very long lines).
- The word list: the reader accepts the real file and refuses a short, long, repeated or misshapen one; the constant, `LICENSES.md` and the file agree.
- Purity, as in section 2.

### Browser, against a build

- Each of the twelve tools produces a result, and Copy puts it on the clipboard.
- A sentinel string is typed into every text box and every generator is run; no request the page makes carries the sentinel or any generated value, in its address, headers or body.
- The only requests after the page has loaded are the word list, once the passphrase tool is opened, and the converters' worker script, once a converter is first used.
- Local storage, session storage and cookies hold nothing from this page.
- A fragment naming a tool opens it; an unknown fragment opens Password.
- A blocked word list shows the passphrase tool's failure and its retry.
- The page passes the Content Security Policy with no violation reported.
- Both themes, and a phone width.

Every new browser context uses `visitor()`, as the other specs do.

### Screens

`capture-pages.mjs` writes each tool's state in light and dark to `apps/web/.impeccable/review/`.
